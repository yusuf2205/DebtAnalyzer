# Безопасность

Документ описывает, что защищено, **чем это проверено** и какие риски приняты осознанно. Эксплуатация — `docs/RUNBOOK.md`.

## Модель угроз
Приложение с финансовыми данными, доступное из интернета только через Cloudflare Tunnel и Cloudflare Access. Основные риски: подбор/кража учётных данных, инсайдерские ошибки и злоупотребления (двойной учёт, правка подтверждённых платежей), вредоносные файлы при импорте, повреждение/потеря данных, утечка секретов.

## Контроли и как они проверены
| Требование ТЗ | Реализация | Проверка |
|---|---|---|
| HTTPS | Терминация TLS в Cloudflare; в приложении — HSTS (web, API), cookie `Secure` + префикс `__Host-` в production | тест: cookie `__Host-`, `Secure`, `HttpOnly`, `SameSite=Lax`, без `Domain`; обычное имя cookie не принимается |
| Безопасная авторизация, хеширование | Argon2id; единое сообщение для неверного email/пароля + выравнивание времени ответа; блокировка 15 мин после 5 неудач; обязательная смена начального/временного пароля | тесты API (хеш `$argon2id$`, 401 одинаков, 423 после 5 неудач, E2E смены пароля) |
| Защищённые сессии | Непрозрачный токен 256 бит, в БД только SHA-256; HttpOnly; TTL 12 ч; выход и отключение пользователя аннулируют сессии | тесты: просроченная/отозванная сессия → 401 |
| CSRF | Токен на сессию в заголовке для всех изменяющих запросов (сравнение за постоянное время) + SameSite=Lax; CORS выключен | тесты: без токена 403; чужой Origin не получает разрешения |
| XSS | React экранирует вывод; **CSP с одноразовым nonce** (`script-src 'self' 'nonce-…' 'strict-dynamic'`, `object-src 'none'`, `frame-ancestors 'none'`); API отдаёт только JSON + `nosniff`; загруженные документы — только как вложение с фиксированным типом | E2E в реальном браузере под CSP без нарушений; тест XSS-строки в данных |
| SQL Injection | Prisma (параметризация); сырые запросы только tagged-шаблонами; параметры сортировки/фильтров — белые списки (zod); NUL-байт отклоняется до БД | тест: 7 инъекционных строк × 6 эндпоинтов — данные целы, хеши не раскрываются; сорт-параметры → 400 |
| Ограничение запросов | Глобально 300/мин на IP, вход — 10/мин (настраивается), корректный IP клиента за прокси (`TRUST_PROXY_HOPS=2`) | тесты: 429 на перебор, другой клиент не затронут; подделанный `X-Forwarded-For` игнорируется |
| Токены Google | AES-256-GCM, ключ только в окружении; права `spreadsheets.readonly` (не весь Drive); `state` OAuth в HttpOnly cookie | тесты: в БД нет открытого токена, нет в ответах API |
| Права на backend | Единый `AccessGuard` (сессия → CSRF → смена пароля → разрешение), по умолчанию всё закрыто | тесты каждого модуля + E2E: прямые запросы наблюдателя/менеджера → 403 |
| Настраиваемые роли | SUPER_ADMIN отмечает права (28) в разделе «Роли и права»; действующие права читаются из БД на каждый запрос — правка роли действует сразу. `roles.manage` нельзя выдать роли (проверка в коде **и** CHECK-ограничение БД); действие требует право просмотра раздела; роль с пользователями не удаляется; не-SUPER_ADMIN назначает только роли в рамках собственных прав; все изменения — в аудите (`role.create/update/delete` с составом добавленных/снятых прав) | 11 интеграционных тестов (права на сервере, мгновенное действие, эскалация, аудит, ограничения БД) + E2E в браузере |
| Журнал аудита | Все финансовые и административные действия, экспорт, вход; **неизменяем триггером БД**; суммы — строками | тест: `UPDATE/DELETE/TRUNCATE` отклоняются |
| Защита от повторной отправки | Ключ идемпотентности платежей; атомарные переходы статусов; блокировка договора при подтверждении; атомарный commit импорта | тесты гонок: двойное подтверждение, двойной коммит, параллельные платежи |
| Целостность денег | Decimal/NUMERIC; подтверждённый платёж неизменяем и не удаляется (триггер); сторно — отдельной записью | тесты + прямые попытки `UPDATE/DELETE` в БД |
| Загрузки | Белый список расширений, проверка сигнатуры файла, лимит размера (413), имя файла очищается | тесты: поддельный XLSX/PDF, превышение лимита |
| БД не в интернете | `db` — internal-сеть, порты не публикуются | `docker compose config` |
| Резервные копии + проверка | Ежедневно, контрольные суммы, еженедельное автоматическое восстановление в отдельную БД с проверкой инвариантов | 38 тестов скриптов (на заглушках); **реальные утилиты — проверка на NAS** |
| Секреты вне Git | `.env` в `.gitignore`; `preflight.sh` отказывает при слабых/пустых секретах | тесты `preflight.sh` |

Дополнительно: журнал запросов без тел/cookie; `X-Request-Id`; страница «Система» предупреждает о небезопасной конфигурации (cookie без Secure в production, начальный пароль в окружении, устаревшие копии, неудачная проверка восстановления).

## Найденное и исправленное в M7
- Web проксировал `/api` на адрес, зашитый при сборке (`localhost:4000`): в Docker приложение не работало бы вовсе. Исправлено (build arg `API_INTERNAL_URL`), E2E собирает web как образ.
- Гонка двойного нажатия «отправить платёж» могла вернуть 409 вместо уже созданного платежа. Исправлено.
- NUL-байт в строке поиска вызывал 500. Исправлено централизованно.
- `GET /fx/rates?status=…` с неверным значением вызывал 500. Исправлено.
- Уязвимость `zod` (DoS на больших коллекциях, high): обновлён до 4.x.
- Подписи a11y: недоступные действия не объявляются как доступные.

## Принятые риски (осознанно)
| Риск | Почему принят | Что делать |
|---|---|---|
| `npm audit`: Prisma CLI → `deepmerge-ts`, `effect` (high); Next → `postcss` (high/moderate) | Затрагивают только инструменты **сборки/CLI** на собственных доверенных файлах (схема, CSS), недостижимы через пользовательский ввод; исправления требуют мажорных версий (Prisma 7, Next 16) | Плановое обновление мажорных версий после проверки на тестовом стенде |
| `exceljs → uuid` (moderate) | Уязвимость только для `uuid` v3/v5/v6 с аргументом `buf`; ExcelJS его не использует | Следить за обновлением `exceljs` |
| SUPER_ADMIN может подтвердить платёж, созданный им самим | В малой команде единственный администратор иначе заблокирован; факт «самоподтверждения» пишется в аудит | Заведите отдельного пользователя FINANCE и не работайте под SUPER_ADMIN |
| `cloudflare/cloudflared:latest` | Версионный тег нужно выбрать после проверки на NAS | Зафиксируйте тег |
| Поиск без учёта регистра для кириллицы в части экранов (контрагенты, договоры) зависит от локали PostgreSQL | В Docker-образе локаль `C.UTF-8`; фильтры дашборда/отчётов не зависят от локали | При необходимости — ICU-локаль БД |
| Пароли от 4 символов (решение владельца) | Защита от подбора: блокировка на 15 мин после 5 неудач, лимит запросов, Cloudflare Access | Не отключать Cloudflare Access; при желании ужесточить `MIN_PASSWORD` в `auth.service.ts` |
| Нет двухфакторной аутентификации в самом приложении | Закрывается Cloudflare Access (SSO/OTP) | Включить Access |
| Контейнеры не `read_only` | Не проверено без Docker — риск не запуститься | После проверки на NAS добавить `read_only: true` + `tmpfs: /tmp` |
