# Procurement Finance

Контроль договоров снабжения, задолженности перед поставщиками, оплат и планов платежей.
Монорепозиторий: `apps/web` (Next.js), `apps/api` (NestJS + Prisma; `src/worker.ts` — фоновые задачи на pg-boss), `packages/shared` (финансовый движок, движок импорта, RBAC).

## Разработка
```sh
npm install
npm run build:shared
node apps/api/scripts/dev-db.mjs 54331 apps/api/.pgdata   # локальный PostgreSQL без Docker
cp .env.example .env  # или задайте DATABASE_URL, INITIAL_ADMIN_* в окружении
cd apps/api && npx prisma migrate deploy && npm run build && npm start
cd apps/web && npm run dev
npm test                                   # shared + api
npm run test:deploy                        # скрипты развёртывания
E2E_CHANNEL=msedge npm run test:e2e        # браузерные сценарии (собранные shared/api; web соберётся сам)
```
Тесты: `packages/shared` (70, включая опциональный прогон по реальному файлу: `PF_REAL_XLSX=путь`), `apps/api` (147, на настоящей БД), `e2e` (21 сценарий в браузере), `deploy/tests` (38, скрипты развёртывания).

## Ключевые принципы
- Все деньги — Decimal / NUMERIC(24,2); округление только на границе. Валюты не суммируются без явного курса.
- Исходные значения сохраняются без правок (`ImportRow.data.raw`); любые приведения (EURO→EUR, пустое «Оплачено»→0) видны в отчёте.
- «Оплачено» из файла — начальный остаток договора, фиктивных платежей нет. Повторный импорт не перезаписывает финансы: создаёт задачу сверки.
- Курсы из файлов — только кандидаты; действующим курс становится после подтверждения пользователем.
- Права проверяются на backend (`AccessGuard`): сессия → CSRF → смена пароля → разрешение. Журнал аудита неизменяем триггером БД.

Эксплуатация: `docs/RUNBOOK.md`.

## Платежи и сверка (M4) — правила
- Платёж: `DRAFT → PENDING → APPROVED | REJECTED`, `CANCELLED`. В долг входят **только APPROVED**. Валюта платежа = валюте договора.
- Подтверждает другой сотрудник с правом `payments.approve` (создавший не может; исключение — SUPER_ADMIN, фиксируется в аудите). Переплата — только с явным подтверждением; возврат не больше оплаченного.
- Подтверждённый платёж неизменяем и не удаляется (триггер БД). Исправление — сторно (отдельная запись) + новый платёж на подтверждение.
- Повторная отправка формы не создаёт второй платёж (ключ идемпотентности). Подтверждение блокирует договор (`FOR UPDATE`), гонки исключены.
- Сверка: изменение «Оплачено» в источнике → задача. Платежи приложения, уже входящие в новое значение, помечаются «учтены в начальном остатке» и не вычитаются повторно. Прирост больше выбранных платежей — только с явным принятием расхождения; больше прироста — запрещено (двойной учёт).
- Платёж в валюте, отличной от валюты договора, не поддерживается (кросс-валютные оплаты потребуют отдельной конвертации).

## Календарь платежей (M5) — правила
- План — отдельная сущность (`PlanEntry`), один план на «договор + год + месяц + неделя». План **никогда не уменьшает долг**.
- Недели W1–W4 не имеют дат в исходном файле, поэтому границы — настройка (по умолчанию 1–7, 8–14, 15–21, 22–конец месяца; меняют администраторы, изменение пишется в аудит). Граница определяет, к какой неделе относится дата подтверждённого платежа.
- Факт = чистая сумма подтверждённых платежей приложения по дате платежа (оплаты − возвраты − сторно). Историческая оплата из файла (без дат) в факт не входит.
- Остаток плана = невыполненная часть по каждому договору и неделе; «сверх плана» — отдельно. Итоги — строго по валютам.
- Просрочено = невыполненный план прошедших недель, но не больше текущего долга по договору (плановые суммы оплаченных договоров из таблицы — это история, а не просрочка).
- Правка импортированной плановой записи делает её ручной: повторный импорт её не перезаписывает. Операции: добавить, изменить, перенести (на занятую неделю суммы складываются), разделить (сумма частей строго равна исходной), удалить.

## Dashboard и отчёты (M6) — правила
- **USD-эквивалент** считается только по **подтверждённым** курсам (раздел «Курсы валют»). Для отчёта на дату D берётся последний курс с датой действия ≤ D — появление новых курсов не меняет прошлые отчёты. Нет курса — нет пересчёта: эквивалент не угадывается, а итог помечается неполным и называет валюты без курса. В каждой строке показываются сумма в исходной валюте, эквивалент, использованный курс и его дата.
- Суммы в разных валютах не складываются. Итог в USD = сумма эквивалентов итогов по валютам.
- Дашборд: суммы договоров/оплаты/долг — на текущий момент (фильтры: валюта, проект, контрагент, исполнитель, статус); период влияет на «план и факт». «Оплачено» = исторический остаток из файла + подтверждённые платежи.
- Динамика задолженности — ежедневные неизменяемые снимки портфеля (дашборд создаёт снимок при открытии, воркер — раз в сутки); историю до первого снимка восстановить нельзя.
- Отчёты: общая задолженность, по поставщикам, по договорам, фактические оплаты (курс на дату платежа), план, план против факта, просроченные, переплаты, по проектам, по исполнителям, валютная аналитика. Excel — с шапкой, фильтрами, форматами чисел и итогами; PDF — с кириллическим шрифтом DejaVu; CSV — UTF-8 с BOM, разделитель «;». Экспорт пишется в журнал аудита.
- Текстовые фильтры (проект, исполнитель) регистронезависимы для кириллицы и не зависят от локали БД.
